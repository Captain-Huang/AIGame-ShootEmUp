# 打飞机小游戏开发执行计划

## 1. 文档目的

本文档用于把《打飞机小游戏需求文档》转化为可直接执行的 Unity 开发计划。后续开发时优先遵循本文档的模块拆分、目录规范、数据结构、里程碑和验收标准。

本文档不替代需求文档。需求文档回答“游戏要做成什么样”，本文档回答“先做什么、怎么组织、怎么验收”。

## 2. 开发原则

- 先做可玩的核心循环，再补表现和打磨。
- 第一版使用占位美术，不因为美术资源阻塞玩法开发。
- 关卡、敌人、子弹、道具、Boss 等可调内容使用 ScriptableObject 配置。
- 玩家进度和设置使用本地存档，不写入 ScriptableObject。
- 子弹、敌人、特效、道具使用对象池，避免频繁 Instantiate 和 Destroy。
- 所有核心系统优先做清晰、稳定、可调，不追求过早复杂化。
- PC 键盘输入优先，移动端触控预留接口但不作为第一阶段必须项。

## 4. 场景规划

### 4.1 MVP 阶段

MVP 阶段只需要一个场景：

| 场景 | 用途 |
| --- | --- |
| Game | 承载主菜单、游戏流程、暂停、结算，可通过 UI 面板切换状态 |

### 4.2 完整阶段

后续可拆分为：

| 场景 | 用途 |
| --- | --- |
| MainMenu | 主菜单、关卡选择、设置 |
| Game | 核心战斗 |
| Boot | 可选，初始化全局服务 |

第一版建议保持单场景，减少流程复杂度。

## 5. 分层架构

### 5.1 运行层

运行层负责游戏中实时执行的逻辑：

- 玩家移动和射击。
- 敌人移动和攻击。
- 子弹飞行和碰撞。
- 波次生成。
- Boss 阶段切换。
- 道具掉落和拾取。
- UI 刷新。
- 音效播放。

### 5.2 配置层

配置层负责数值和资源引用：

- `PlayerConfig`
- `WeaponConfig`
- `BulletConfig`
- `EnemyConfig`
- `BossConfig`
- `BossPhaseConfig`
- `PickupConfig`
- `WaveConfig`
- `LevelConfig`
- `LevelDatabase`

### 5.3 表现层

表现层负责视觉和声音反馈：

- Sprite。
- 材质。
- 粒子特效。
- 爆炸动画。
- 受伤闪烁。
- 屏幕震动。
- UI 动效。
- 音效和背景音乐。

### 5.4 存档层

存档层负责玩家长期数据：

- 最高解锁关卡。
- 每关最高分。
- 总最高分。
- 音量设置。
- 全屏设置。

MVP 使用 `PlayerPrefs`。后续如果数据变复杂，再改成 JSON 本地存档。

## 7. ScriptableObject 配置设计

### 7.1 LevelDatabase

用途：保存所有关卡入口。

字段建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| levels | LevelConfig[] | 所有关卡配置 |
| firstLevel | LevelConfig | 默认第一关 |

资产路径：

```text
Assets/Game/Configs/Database/LevelDatabase.asset
```

### 7.2 LevelConfig

用途：单个关卡的完整配置。

字段建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| levelId | int | 关卡编号，1 到 5 |
| displayName | string | UI 显示名 |
| difficulty | int | 难度等级 |
| estimatedDuration | float | 预计时长 |
| backgroundSprite | Sprite | 背景图，可先为空 |
| bgm | AudioClip | 关卡音乐，可先为空 |
| bossBgm | AudioClip | Boss 音乐，可先为空 |
| waves | WaveConfig[] | 普通波次 |
| bossConfig | BossConfig | 关底 Boss |
| preBossSupplyWave | WaveConfig | Boss 前补给波，可选 |
| enemyHealthMultiplier | float | 敌人生命倍率 |
| enemyFireRateMultiplier | float | 敌人射击频率倍率 |
| scoreBonus | int | 通关基础奖励 |

资产路径：

```text
Assets/Game/Configs/Levels/Level_01.asset
Assets/Game/Configs/Levels/Level_02.asset
Assets/Game/Configs/Levels/Level_03.asset
Assets/Game/Configs/Levels/Level_04.asset
Assets/Game/Configs/Levels/Level_05.asset
```

### 7.3 WaveConfig

用途：定义一波敌人或补给。

字段建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| waveId | string | 波次 ID |
| startDelay | float | 波次开始前延迟 |
| entries | WaveEntry[] | 本波生成内容 |
| waitUntilAllEnemiesDead | bool | 是否等待本波敌人全灭 |
| maxDuration | float | 最长持续时间 |

`WaveEntry` 字段建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| enemyConfig | EnemyConfig | 敌人配置 |
| count | int | 数量 |
| spawnInterval | float | 生成间隔 |
| spawnPattern | SpawnPattern | 生成点模式 |
| movementPattern | MovementPattern | 移动模式 |
| horizontalOffset | float | 生成横向偏移 |
| customSpawnPoints | Vector2[] | 自定义生成点 |

资产路径：

```text
Assets/Game/Configs/Waves/Level01/Wave_01_01.asset
```

MVP 可先把波次作为 `LevelConfig` 内联序列化数据；如果 Inspector 太长，再拆成独立 `WaveConfig.asset`。

| firePattern | FirePattern | 射击模式 |
| fireInterval | float | 射击间隔 |

### 10.2 Collision Matrix

- `Player` 与 `Enemy`
- `Player` 与 `EnemyBullet`
- `Player` 与 `Pickup`
- `Enemy` 与 `PlayerBullet`
- `Boundary` 与 `Enemy`
- `Boundary` 与 `PlayerBullet`
- `Boundary` 与 `EnemyBullet`
- `Boundary` 与 `Pickup`

其他关系默认关闭，降低无意义碰撞。

## 12. 开发里程碑

### 12.1 阶段 0：工程准备

目标：建立项目结构和基础配置。

任务：

- 创建推荐目录。
- 创建 Layer 和碰撞矩阵。
- 创建基础场景结构。
- 创建 GameManager 空对象。
- 创建基础 Canvas。
- 创建占位 Sprite 和材质。

验收：

- 项目目录清晰。
- Game 场景可打开。
- 控制台无报错。
- 可以进入 Play Mode。

### 12.2 阶段 1：核心战斗闭环

目标：玩家可以移动、射击、击杀敌人、被击败。

任务：

- 实现玩家移动和边界限制。
- 实现玩家自动射击。
- 实现子弹移动和碰撞。
- 实现普通敌人生成和移动。
- 实现敌人受击、死亡和计分。
- 实现玩家生命、受伤、死亡。
- 实现基础 HUD。

验收：

- 玩家可在屏幕内移动。
- 玩家子弹可以击毁敌人。
- 敌人可伤害玩家。
- 玩家死亡后进入失败状态。
- 分数和生命 UI 正常刷新。

### 12.3 阶段 2：ScriptableObject 配置

目标：用配置驱动玩家、敌人、子弹、道具和关卡。

任务：

- 创建配置脚本。
- 创建 PlayerConfig。
- 创建 BulletConfig。
- 创建 EnemyConfig。
- 创建 PickupConfig。
- 创建 LevelConfig。
- 创建 LevelDatabase。
- 将运行逻辑改为读取配置。

验收：

- 修改配置资产后，运行效果随之改变。
- 至少 3 种敌人由不同 EnemyConfig 驱动。
- 至少 1 个 LevelConfig 能驱动完整波次。

### 12.4 阶段 3：波次和关卡流程

目标：完成 5 关普通波次流程。

任务：

- 实现 WaveSpawner。
- 实现 LevelManager。
- 创建 5 个 LevelConfig。
- 配置每关普通波次。
- 实现关卡胜利和下一关。
- 实现关卡解锁。

验收：

- 可以从第 1 关进入战斗。
- 普通波次按顺序生成。
- 当前关完成后进入结算。
- 可以进入下一关。
- 5 关都能跑通普通波次。

### 12.5 阶段 4：Boss 系统

目标：每关有 Boss，Boss 有阶段变化。

任务：

- 实现 BossController。
- 实现 Boss 阶段切换。
- 实现 Boss 血条。
- 创建 5 个 BossConfig。
- 配置每关 Boss。
- 实现 Boss 死亡演出和通关判定。

验收：

- 每关末尾出现 Boss。
- Boss 血条正常显示。
- Boss 能根据血量切换攻击模式。
- 击败 Boss 后关卡胜利。
- 第 5 关 Boss 死亡后进入最终通关结算。

### 12.6 阶段 5：道具和火力成长

目标：玩家能通过拾取道具改变战斗节奏。

任务：

- 实现 Pickup。
- 实现掉落表。
- 实现火力升级。
- 实现生命恢复。
- 实现炸弹数量。
- 实现护盾。
- 实现炸弹清屏。

验收：

- 敌人死亡能按概率掉落道具。
- 拾取火力道具能提升火力等级。
- 拾取生命道具能恢复生命。
- 拾取炸弹道具能增加炸弹。
- 炸弹能清除敌方子弹并伤害敌人。
- 护盾能抵挡一次伤害或持续一段时间。

### 12.7 阶段 6：UI、音频、存档

目标：补齐完整游戏流程。

任务：

- 主菜单。
- 暂停界面。
- 失败界面。
- 关卡结算界面。
- 通关结算界面。
- 设置界面。
- 音频管理。
- 本地进度保存。

验收：

- 所有菜单按钮可用。
- 可暂停和恢复。
- 失败后可重试。
- 通关后显示最终结算。
- 最高解锁关卡可保存。
- 音量设置可保存。

### 12.8 阶段 7：表现和打磨

目标：让游戏从“能玩”变成“像游戏”。

任务：

- 背景滚动。
- 爆炸特效。
- 命中特效。
- 拾取特效。
- 玩家受伤闪烁。
- Boss 出场提示。
- Boss 死亡多段爆炸。
- 屏幕震动。
- 音效和 BGM。
- 难度调参。

验收：

- 所有关键行为都有反馈。
- 5 关难度递增明显。
- 不存在明显卡关或过度拖沓。
- 控制台无运行时报错。

## 13. MVP 开发顺序

建议最小可玩版本按以下顺序执行：

1. 创建目录、Layer、基础场景。
2. 创建玩家 Prefab，占位 Sprite，移动脚本。
3. 创建玩家子弹 Prefab，自动射击。
4. 创建敌人 Prefab，直线移动。
5. 完成子弹击中敌人。
6. 完成敌人碰撞或子弹伤害玩家。
7. 创建 GameManager 和 HUD。
8. 创建 ScriptableObject 配置脚本。
9. 创建第 1 关 LevelConfig 和基础波次。
10. 创建 Boss 基础逻辑。
11. 扩展为 5 关配置。
12. 增加道具和火力升级。
13. 增加结算、失败、暂停。
14. 增加表现、音效、存档。

## 15. 5 关配置落地策略

第一版创建完整 5 个 `LevelConfig.asset`，但可以逐步填充：

| 阶段 | 关卡配置状态 |
| --- | --- |
| 阶段 3 | 5 关普通波次可运行，Boss 可先为空或使用同一 Boss |
| 阶段 4 | 5 关 BossConfig 全部填入 |
| 阶段 5 | 5 关道具掉落和补给波完整 |
| 阶段 7 | 5 关背景、音乐、难度参数调完 |

这样可以较早验证“5 关连续通关”的主流程。

## 16. 调试工具建议

建议开发期间保留以下调试能力：

- 一键进入指定关卡。
- 玩家无敌开关。
- 增加火力等级。
- 增加炸弹数量。
- 立即生成 Boss。
- 清除所有敌人和子弹。
- 显示对象池数量。

调试功能可放在 `DebugGamePanel` 或仅在 Editor 下启用。

## 17. 验收总清单

完成基础版本时必须满足：

- 可以从主菜单开始游戏。
- 玩家可移动、射击、受伤、死亡。
- 有 5 个关卡配置。
- 5 个关卡都能进入、完成、结算。
- 每关有普通波次和 Boss。
- 难度从第 1 关到第 5 关递增。
- 有火力、生命、炸弹、护盾道具。
- 有分数系统和评级。
- 有暂停、失败、胜利、通关界面。
- 有本地进度保存。
- 有基础特效和音效入口。
- 核心对象使用对象池。
- Unity 控制台无运行时报错。

## 18. 后续开发时的工作方式

后续每次开发建议按小步执行：

1. 先确认当前目标，例如“实现玩家移动和射击”。
2. 修改或创建必要脚本。
3. 等待 Unity 编译完成。
4. 检查 Console 错误。
5. 创建或更新 Prefab、Config、Scene 对象。
6. 进入 Play Mode 验证。
7. 截图或读取场景状态确认结果。
8. 记录已完成内容和下一步。
