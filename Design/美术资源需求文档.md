# 打飞机小游戏美术资源需求文档

## 1. 文档目的

本文档用于定义打飞机小游戏所需的美术资源范围、风格、规格、命名和交付标准。第一版开发可使用占位资源，后续可根据本文档逐步生成、采购或替换正式美术资源。

本文档重点服务两个场景：

- 开发阶段：明确需要哪些占位资源，避免玩法开发被美术阻塞。
- 美术生产阶段：作为生成图片、制作 Sprite、整理资源包的依据。

## 2. 美术方向

### 2.1 推荐风格

推荐采用 2D 科幻街机空战风格：

- 俯视或轻微 2.5D 俯视角。
- 画面清晰，剪影容易识别。
- 玩家、敌人、子弹、道具颜色区分明显。
- 特效明亮但不遮挡弹幕判断。
- 整体适合快速移动和大量对象同屏。

### 2.2 不推荐的方向

第一版不建议：

- 使用复杂 3D 模型。
- 使用写实高精度贴图。
- 使用难以辨认的小细节飞机。
- 使用过暗、过灰、过多同色系的画面。
- 使用与弹幕颜色冲突的背景。

### 2.3 画面关键词

```text
2D
vertical shoot em up
arcade
sci-fi aircraft
clear silhouette
high readability
color-coded bullets
clean effects
mobile-friendly
```

## 3. 技术规格

### 3.1 资源格式


| 资源类型   | 推荐格式      | 说明                        |
| ------ | --------- | ------------------------- |
| Sprite | PNG       | 透明背景                      |
| UI 图标  | PNG       | 透明背景                      |
| 背景图    | PNG 或 JPG | 不需要透明                     |
| 特效贴图   | PNG       | 透明背景                      |
| 精灵表    | PNG       | 搭配 Unity Sprite Editor 切割 |


### 3.2 分辨率建议

第一版以竖屏 9:16 为基础设计。


| 资源    | 推荐尺寸              |
| ----- | ----------------- |
| 玩家飞机  | 128x128           |
| 小型敌机  | 96x96             |
| 中型敌机  | 128x128           |
| 护甲敌机  | 160x160           |
| 精英敌机  | 192x192           |
| Boss  | 384x256 或 512x384 |
| 子弹    | 32x64 或 32x32     |
| 道具    | 64x64             |
| 爆炸单帧  | 128x128           |
| 背景    | 1080x1920         |
| UI 图标 | 64x64 或 128x128   |


### 3.3 Sprite 设置建议

Unity 导入设置建议：


| 项                 | 建议                 |
| ----------------- | ------------------ |
| Texture Type      | Sprite             |
| Sprite Mode       | Single 或 Multiple  |
| Pixels Per Unit   | 100                |
| Mesh Type         | Full Rect          |
| Filter Mode       | Bilinear           |
| Compression       | Normal Quality     |
| Generate Mip Maps | 关闭，2D Sprite 通常不需要 |


像素风格若后续改为像素风，需要将 Filter Mode 改为 Point，并统一像素密度。当前不建议走像素风。

### 3.4 透视和朝向

- 玩家飞机机头朝上。
- 敌机默认机头朝下。
- Boss 默认从屏幕上方出现，主体朝下。
- 子弹默认向上或向下，具体方向由脚本旋转。
- 道具正面朝向摄像机。

### 3.5 Pivot 建议


| 资源    | Pivot  |
| ----- | ------ |
| 飞机    | Center |
| 子弹    | Center |
| 道具    | Center |
| 爆炸    | Center |
| 背景    | Center |
| UI 图标 | Center |


## 4. 色彩规范

### 4.1 阵营颜色


| 阵营或功能 | 推荐颜色         |
| ----- | ------------ |
| 玩家飞机  | 蓝、白、青色为主     |
| 普通敌机  | 红、橙、灰色       |
| 精英敌机  | 紫、暗红、金属色     |
| Boss  | 深色金属 + 高亮能量色 |
| 玩家子弹  | 青色、蓝色、白色     |
| 敌方子弹  | 红色、橙色、紫色     |
| 火力道具  | 红色或橙色        |
| 生命道具  | 绿色           |
| 炸弹道具  | 黄色           |
| 护盾道具  | 蓝色           |
| 分数道具  | 金色           |


### 4.2 可读性要求

- 玩家子弹和敌方子弹必须一眼区分。
- 道具颜色不能与敌方子弹混淆。
- 背景不能抢过弹幕和飞机。
- Boss 弱点或炮口可以用高亮色强调。
- 同屏大量敌人时，轮廓仍需清楚。

## 5. 占位资源方案

### 5.1 占位阶段目标

占位资源用于快速验证玩法，不追求最终观感。占位资源必须满足：

- 能区分玩家、敌人、Boss、子弹、道具。
- 尺寸接近正式资源。
- 碰撞范围容易判断。
- 颜色符合阵营规范。
- 后续替换正式资源时不影响代码结构。

## 6. 正式资源清单

### 6.1 玩家飞机


| 资源                 | 数量  | 尺寸      | 说明          |
| ------------------ | --- | ------- | ----------- |
| PlayerShip_Default | 1   | 128x128 | 默认玩家飞机      |
| PlayerShip_Damaged | 1   | 128x128 | 可选，受伤表现     |
| PlayerShip_Shield  | 1   | 160x160 | 护盾外圈，可用半透明图 |


玩家飞机要求：

- 剪影清晰。
- 机头朝上。
- 中心点明确。
- 不要过宽，避免碰撞判断不舒服。
- 颜色偏蓝、白、青，与敌机明显区分。

### 6.2 普通敌机


| ID  | 名称     | 数量  | 尺寸      | 特征           |
| --- | ------ | --- | ------- | ------------ |
| E01 | 小型直线敌机 | 1   | 96x96   | 简单红色轻型机      |
| E02 | 斜向敌机   | 1   | 96x96   | 更窄、更尖        |
| E03 | 中型射击敌机 | 1   | 128x128 | 有明显炮口        |
| E04 | 快速突击机  | 1   | 96x96   | 速度感强，尖锐轮廓    |
| E05 | 护甲敌机   | 1   | 160x160 | 厚重、金属装甲      |
| E06 | 散弹敌机   | 1   | 128x128 | 多炮口或扇形结构     |
| E07 | 追踪敌机   | 1   | 128x128 | 能量核心或追踪感     |
| E08 | 精英敌机   | 1   | 192x192 | 小 Boss 感，更复杂 |


敌机要求：

- 默认朝下。
- 不同敌人剪影要不同，不能只换颜色。
- 射击型敌人要能看出炮口。
- 护甲敌机要看起来更耐打。
- 快速突击机要看起来轻、窄、快。

### 6.3 Boss


| 关卡  | Boss 名称 | 尺寸      | 设计关键词            |
| --- | ------- | ------- | ---------------- |
| 1   | 巡逻机长    | 384x256 | 小型旗舰、训练关 Boss    |
| 2   | 云层轰炸者   | 384x256 | 轰炸机、厚机翼、弹仓       |
| 3   | 重装炮艇    | 512x320 | 重装甲、多炮口          |

| 5   | 星际母舰    | 640x384 | 大型母舰、多炮台、最终 Boss |


Boss 要求：

- 主体比普通敌机明显更大。
- 炮口、核心、弱点区域可读。
- 每个 Boss 的轮廓和主题不同。
- 第 5 关 Boss 需要有最终 Boss 压迫感。
- 可以先做单张 Sprite，不要求骨骼动画。

| 资源            | 尺寸    | 颜色  | 图形符号    |
| ------------- | ----- | --- | ------- |
| Pickup_Power  | 64x64 | 红/橙 | P 或火力符号 |

### 6.6 背景

需要 5 张关卡背景。


| 关卡  | 背景名                 | 尺寸        | 设计关键词         |
| --- | ------------------- | --------- | ------------- |
| 1   | BG_TrainingAirspace | 1080x1920 | 清晰天空、训练空域、低干扰 |
| 2   | BG_CloudAssault     | 1080x1920 | 云层、速度感、浅色但不刺眼 |
| 3   | BG_FireBlockade     | 1080x1920 | 战区、火光、机械设施    |
| 4   | BG_EliteIntercept   | 1080x1920 | 夜间高空、敌方基地轮廓   |
| 5   | BG_FinalCarrier     | 1080x1920 | 太空或高空母舰战场     |


背景要求：

- 可纵向循环滚动。
- 中心区域不能太花，避免遮挡弹幕。
- 亮度和对比度不能压过子弹。
- 每关主题不同，但整体风格统一。

可选方案：

- 每关使用一张长背景循环。
- 每关使用两张背景图交替滚动。
- 背景加少量粒子星点或云层漂移。

| VFX_Hit_Small        | 粒子或 Sprite | 子弹命中      |

特效要求：

- 爆炸不能遮挡敌方子弹太久。
- 命中特效持续时间建议 0.1 到 0.2 秒。
- 小爆炸持续时间建议 0.4 到 0.6 秒。
- Boss 爆炸可持续 2 到 3 秒。
- 炸弹清屏可以有明显波纹，但不能造成长时间视觉噪音。

## 12. 替换资源流程

正式资源替换占位资源时，建议按以下流程：

1. 将正式 PNG 放入对应 `Assets/Game/Art/` 子目录。
2. 设置 Sprite 导入参数。
3. 替换 Prefab 上的 SpriteRenderer 引用。
4. 检查 Collider2D 是否需要调整。
5. 检查对象池 Prefab 引用是否正常。
6. 进入游戏验证尺寸、朝向和碰撞手感。
7. 截图确认同屏可读性。

替换时不要改脚本逻辑，除非资源尺寸变化导致碰撞、发射点或特效挂点必须调整。

## 13. 验收标准

### 13.1 单个 Sprite 验收

- 背景透明，边缘干净。
- 朝向正确。
- 尺寸符合规格。
- Pivot 居中。
- 小尺寸下仍能识别。
- 不与同阵营其他对象混淆。

### 13.2 游戏内验收

- 玩家和敌人一眼能区分。
- 玩家子弹和敌方子弹一眼能区分。
- 道具不会被误认为敌方子弹。
- 背景不干扰弹幕判断。
- 爆炸和特效不会遮挡危险信息太久。
- Boss 体型和视觉压迫感符合关卡定位。

### 13.3 5 关整体美术验收

- 5 关背景主题不同。
- 5 个 Boss 外形不同。
- 敌人由简单到复杂有递进感。
- 最终关整体压迫感最强。
- 全部资源风格统一，没有明显拼贴感。

## 14. 后续美术开发建议

第一轮先做 P0 资源，完成第 1 关 MVP。确认玩法方向后，再补齐 P1 的完整 5 关资源。最后根据实际游戏画面决定是否需要 P2 打磨资源。

正式美术生产时，应优先保证可读性，其次才是细节丰富度。打飞机游戏同屏对象多，玩家需要在高速状态下判断危险，清晰比华丽更重要。
